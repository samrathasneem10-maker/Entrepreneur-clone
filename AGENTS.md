# Strict Change Requirements – Antigravity Rules

Make changes only to the specific feature, element, or functionality explicitly requested. Preserve all existing designs, features, and behavior.

- **Laptop View**: Modify only when explicitly requested.
- **Desktop View**: Modify only when explicitly requested.
- **Mobile View**: Modify only when explicitly requested.
- **Article Content**: Modify only the specific article or element identified.
- **Page Layout**: Do not change unrelated sections, components, spacing, alignment, or styling.
- **Existing Functionality**: Never remove, overwrite, or break existing features.
- **Code Changes**: Inspect the existing code before editing. Make minimal, targeted changes using component-level updates and appropriate CSS media queries.
- **Responsive Design**: Keep laptop, desktop, and mobile styles independent. A change to one view must not affect the others.
- **Data Integrity**: Do not modify unrelated articles, images, user profiles, categories, or content.
- **No Unrequested Changes**: Do not redesign, rebuild, refactor, or optimize unrelated parts of the website.
- **Verification**: After making changes, verify that the requested feature works correctly and that all unrelated pages, views, and functionality remain unchanged.
- **Preserve Existing Code**: Reuse existing components and styles wherever possible. Avoid duplicate code and unnecessary modifications.

## Golden Rule

Change only what I explicitly request. Keep everything else exactly as it is. If a requested change might affect another page, screen size, component, or feature, isolate the change before applying it. Never make assumptions or introduce additional changes without permission.
